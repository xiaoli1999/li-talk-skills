# 交付前自查和自检报告怎么改

两件事：

1. 交付前的自查清单：给用户看 3 页试做之前、给用户过稿之前，各过一遍。
2. 检查报告里每类问题怎么改：先是不开浏览器的检查（`check`），再是后台浏览器自检（`check --browser`）。

**规矩**：错误必须清零，才能把课件给用户看。提醒逐条判断：要么改，要么跟用户说清为什么不改。看不了图的模型就照报告改，不要猜；报告里每条都写了在哪一页哪一拍、什么问题、量到的数字和怎么改。

---

## 1. 交付前自查清单

### 检查都过了

- [ ] `check <课件目录>`：0 个错误。
- [ ] `check <课件目录> --browser`：0 个错误。必须是完整的一次（不带 `--pages`、`--scene`），只查部分页面或临时换风格的那次不算数，也不会更新自检记录。
- [ ] 改完页面以后重跑过：`guide` 显示「上次自检 … 0 个错误」，而不是「之后页面又改过了」。
- [ ] 每条提醒：改了，或者想好了怎么跟用户说明为什么不改。

### 和讲稿对得上

- [ ] 页数、顺序和讲稿一致；每页 `id` 是讲稿页号（第 5 页是 `p05`）。
- [ ] 屏幕上的字和讲稿「屏幕」一段一字不差，没有自己加字、改字。
- [ ] 每页的拍数和讲稿「节拍」一段一致：拍数 = 翻到这页后要点几下，第 0 拍不算（第 0 拍 + 第 1、2 拍 = 2 拍）；每页 2 到 4 拍，封面和结尾 1 到 2 拍。
- [ ] 截图的说明写在 `figure.shot` 的 `data-caption` 里，屏幕正文里没有「截图说明：」这样的字。
- [ ] 每页的 `notes` 从第 0 拍写到最后一拍，一拍一条，`say` 是讲稿里对应那一拍的讲词。
- [ ] 每拍一个重点词：屏幕上有的标了 `<em class="key">`，`notes` 里写了 `key`。
- [ ] 新概念第一次出现的页，第 0 拍有一句 `.explain` 解释。
- [ ] 讲稿「画面」一段写的版式、形象的站位、要用的截图都做到了。

### 页面本身

- [ ] 除了封面和结尾，每页都有 `topic`，十五个字以内。
- [ ] 大标题 20 个字以内（像素手账 19 个字以内），一行放得下。
- [ ] 一页一个视觉重心，正文不超过约 80 个字。
- [ ] 正文都不小于 34px；用了 `data-small` 的只是编号、图例这类小字。
- [ ] 截图文件都在课件目录里，路径是相对路径（`素材/xx.png`）；提醒过用户截图点开显示原图，敏感信息也会被看到。
- [ ] 最后一页底部留出了署名的位置（y 990 以下没有字）。
- [ ] 只改了 `slides/` 和 `index.html` 两对「章节」注释之间的行（换风格时改的风格引入行除外）。
- [ ] 能看图的话：跑过 `check <课件目录> --browser --shots`，逐张看了 `.li-talk/shots/` 里的截图：没有挤成一团、形象没挡字、颜色和风格协调。

### 给用户看的时候

- [ ] 用 `open <课件目录>` 打开给用户看。
- [ ] 告诉用户怎么看：→ 或空格下一拍，← 上一拍，S 演讲者视图（看讲词），T 计时开始或暂停，R 计时归零，F 全屏。
- [ ] 问用户行不行，等用户明确说可以，再运行对应的 `confirm`（3 页试做是 `trial`，过稿是 `review`）。

## 2. 报告怎么读

### 不开浏览器的检查（`check`）

```
检查：7 页，2 个错误、1 个提醒

错误
  第 3 页 p03：没写 title
    → 加上标题，演讲者视图和阅读模式要用
  slides/ch1.css 第 4 行：选择器「.card」没以 [data-id="…"] 开头
    → 在选择器前面加上 [data-id="页面id"]
提醒
  第 5 页 p05：讲词写到第 3 拍，页面写到第 2 拍
    → 让讲词和节拍一一对应：从第 0 拍写到页面的最后一拍，一拍一条

信息
  讲词共 1520 字，按每分钟 220–250 字估，大约讲 6–7 分钟
```

每条两行：第一行是在哪、什么问题，第二行 `→` 后面是怎么改。几秒出结果，每写完一章就跑一次。

### 后台浏览器自检（`check --browser`）

```
自检报告：12 页 38 拍 × 5 个尺寸，3 个错误、2 个提醒

错误
  第 4 页 p04「三种安装方式」第 2 拍｜1440×900、1280×720
    第 3 张卡片的文字超出卡片底边 46px（卡片高 300，内容高 346）
    → 删减这块的文字，或去掉容器的固定宽高
```

- 第一行：第几页、id、标题、第几拍｜在哪几个尺寸下出现。和具体页无关的问题写「整份课件」。
- 第二行：量到了什么，带着数字。
- 第三行：`→` 后面是怎么改。
- 同一个问题在几个尺寸都出现时合成一条，尺寸列在一起。
- 自检用本机的 Edge 或 Chrome 在后台跑，不弹窗口；查 5 个尺寸：1920×1080、1440×900、1280×720、1024×768，以及手机竖屏 390×844（阅读模式）。

### 只查几页、看截图

- `check <课件目录> --browser --pages 3-5`：只查第 3 到 5 页，改某几页时快一些。但最后必须完整跑一次。
- `check <课件目录> --browser --shots`：另外给每页的最后一拍截一张 1920×1080 的图，存在 `<课件目录>/.li-talk/shots/p01.png` 这样的文件里。能看图的模型可以打开看；看不了图的不用加。
- 退出码：0 没有错误，1 有错误，2 环境问题（比如找不到浏览器、Node 版本太低）。

## 3. 不开浏览器的检查：每条怎么改

| 报告里写的 | 原因 | 怎么改 |
|---|---|---|
| `第 n 页：id「x」和第 m 页重复` | 两页用了同一个 id | 改成全稿唯一的 id，用讲稿页号（p05） |
| `第 n 页没写 id` | `Deck.add` 里少了 `id` | 加上 `id: 'p05'` 这样的讲稿页号 |
| `第 n 页 id：没写 title` | 少了 `title` | 加上标题；封面、结尾用了 `noTitle: true` 也要写 `title` |
| `第 n 页 id：没写主题行 topic`（提醒） | 中间的页没写 `topic` | 照讲稿「主题」一行的后半截写 `topic` |
| `第 n 页 id：没写风格 scene` / `风格「x」没有引入` | `scene` 没写、写错，或这个风格没放进课件 | 换成报告里列出的已引入风格；真要用新风格，照 styles.md「搭好骨架后换风格」做 |
| `风格混用了不同的家：…`（提醒） | 手绘家和现代家混在一份课件里 | 只用同一家的风格（见 styles.md 第 4 节）；用户坚持要混，跟用户说明后可以不改 |
| `第 n 页 id：找不到文件 x` | 图片、视频的路径不对，或文件不在课件目录里 | 把文件放进课件目录（比如 `素材/`），路径写成相对 `index.html` 的路径，注意大小写和扩展名 |
| `文件 第 n 行：选择器「x」没以 [data-id="…"] 开头` | 页面 CSS 写了全局选择器 | 每一段都改成以 `[data-id="页面id"]` 开头；逗号分开的每一段都要带 |
| `第 n 页 id：带拍的元素上写了 transform` | 带 `data-beat` 的元素 `style` 里有 `transform` | 位置改用 `left` / `top`，倾斜改用 `--r`（比如 `--r:-2deg`） |
| `第 n 页 id：讲词写到第 a 拍，页面写到第 b 拍`（提醒） | `notes` 的最后一拍和页面的最后一拍对不上 | 每拍一条讲词，从第 0 拍写到最后一拍；或者是页面少写/多写了一拍，照讲稿「节拍」一段改 |
| `第 n 页 id：翻到这页后要点 b 下（有 b 拍），建议 2 到 4 拍`（提醒） | 普通页拍太多或太少。拍数 = 要点几下，第 0 拍不算：第 0 拍 + 第 1 拍只有 1 拍 | 太多就拆成两页（讲稿也要跟着拆，并告诉用户）；太少就把已有的内容分到不同的拍出现（比如截图第 1 拍、圈注或形象第 2 拍），或和前后页合并。**不要为了凑拍数往屏幕上加讲稿里没有的字**；真要改屏幕，先改讲稿并告诉用户 |
| `第 n 页 id：这是封面页，翻到这页后要点 b 下（有 b 拍），建议 1 到 2 拍` / `这是结尾页，…`（提醒） | 第一页、最后一页拍太多或太少 | 只有第 0 拍（要点 0 下）时，让副标题或最后一句第 1 拍出现；太多就把内容挪到别的页。讲稿页数比课件多时（比如先做 3 页），最后一页不算结尾，按普通页查 |
| `文件 第 n 行：用了 …，课件里不能用` | 越过了技术边界 | 见 authoring.md 的「技术边界」一节，表里有每种写法怎么改 |
| `index.html 引入了 x，但文件不存在` | 引入了还没建的文件 | 建这个文件（新章节的 css 也要建，可以只写一行注释），或删掉这行引入 |
| `x 没有在 index.html 里引入，里面的页面不会显示`（提醒） | 建了章节文件但没引入，或引入写在了章节注释外面 | 在 `index.html` 两对「章节」注释之间各加一行（见 authoring.md 第 1 节）；不要的文件就删掉 |
| `x 运行出错，这一章没查到：…` | 章节文件有语法错误或运行时报错，这一章的页面一页都没加载 | 照错误信息和行号改：常见的是少了逗号、括号没配对、`html` 里的反引号没转义 |

## 4. 后台浏览器自检：每类问题怎么改

下面每一节对应报告里的一类问题。括号里是引擎给这类问题起的类型名，报告里不显示，按「报告里长这样」对上就行。

### 超出舞台（out-of-stage）

- **报告里长这样**：`「这一段字」超出舞台右边 120px（舞台 1920×1080）`
- **原因**：这块的字有一部分跑到了 1920×1080 外面，投出来会被切掉。常见的是 `left` + `width` 超过了 1920、一句话解释（不换行）太长、长命令太长、散落再归位的位置算错了。
- **怎么改**：
  1. 按报告的数字往里挪：超出右边 120px，就把 `left` 减 120 以上，或把 `width` 减 120 以上（多留 20px 余量）。
  2. 挪不动就删减文字。一句话解释控制在 30 个字以内；命令一行最多约 70 个字符。
  3. 内容区是 x 120–1800、y 240–980，写位置时别超出这个范围。

### 文字超出容器（text-overflow）

- **报告里长这样**：`第 3 张卡片的文字超出卡片底边 46px（卡片高 300，内容高 346）`
- **原因**：容器（卡片、终端、命令、小格、步骤、标签、截图、金句，或者带底色、边框的块）装不下里面的字。最常见的是给卡片写死了 `height` 或 `width`。
- **怎么改**：
  1. 删减这块的文字（首选：屏幕上的字本来就该短）。删字要和讲稿「屏幕」一段同步，并告诉用户。
  2. 去掉容器写死的 `height`，要等高改成 `min-height`；或者把容器加宽。
  3. 超出右边：文字在容器里不换行（比如 `nowrap`、命令），把容器加宽或删字。
- **别这样改**：把字号改到 34px 以下。

### 文字互相压（overlap）

- **报告里长这样**：`「A」和「B」叠在一起（交叠约 300×40px，占小的那块的 60%）`
- **原因**：两块文字的位置重叠了。常见的是两块绝对定位的元素 `top` 太近、大标题太长换了行压住下面的一句话解释、上一块的字比预想的多。
- **怎么改**：
  1. 按交叠尺寸挪开：交叠高 40px，就把下面那块的 `top` 加 40 以上，再多留 20px。
  2. 大标题压住一句话解释：把标题改短到一行（20 个字以内）。
  3. 空间不够就删字或拆页。

### 形象挡字（mascot-cover）

- **报告里长这样**：`形象的身子压住了「动手前，准备三样东西」（交叠约 134×6px）`，或 `形象的气泡压住了…`
- **原因**：形象这一拍站的位置压住了字。形象的位置由这一拍目标元素上的 `data-mascot-side`、`-x`、`-dx`、`-dy` 决定。
- **怎么改**（在这一拍的目标元素上，也就是写着 `data-mascot="这一拍"` 的那个元素上改）：
  1. 换一侧：`data-mascot-side="bottom"`（一排卡片、横排步骤最常用）、`right`、`left`。站上沿（`top`，默认）时上方要空出一个形象高，紧挨着标题的元素不要站上沿。
  2. 微调：按交叠尺寸挪，交叠 134×6px 就加 `data-mascot-dy="24"`（往下）；横向压住就用 `data-mascot-dx`（负数往左）。
  3. 气泡压字：去掉 `data-mascot-say`，或者让形象站到上方空的地方。
  4. 第 0 拍形象还没有目标时，它待在 `<div class="mascot guide">` 的 `style` 位置：把起点挪到不挡字的地方（右下角 `left:1680px;top:860px` 通常是空的）。

### 进了风格的禁区（zone）

- **报告里长这样**：`「这一段字」进了风格的禁区「粉笔槽」（交叠约 400×20px）`
- **原因**：每种风格有几块地方不能放字：主题行、右上角的页码和节拍格、方格纸左边的活页孔、黑板底部的粉笔槽和板擦。
- **怎么改**：把这块往里挪出禁区。各风格的禁区坐标见 styles.md 第 3 节：粉笔槽是 y 1000 以下（内容底边留在 y 980 以上），活页孔是 x 66 以内，页码和节拍格在右上角 x 1340 以右、y 90 以上。

### 字太小（font-small）

- **报告里长这样**：错误 `「说明文字」字号 28px，小于 34px`；提醒 `「出处」标了 data-small，字号 20px，小于 24px`
- **原因**：正文小于 34px；或者标了 `data-small` 的小字小于 24px。
- **怎么改**：
  1. 正文改到 34px 以上（直接删掉自己写的 `font-size`，默认就是 36px）。放不下就删字、拆页，不要缩字。
  2. 确实是注释类的小字（编号、图例、出处），在那个元素上加 `data-small`，字号不小于 24px。小格 `.cell` 里的 `<i>` 编号和截图说明不用加，自检本来就按小字查。
  3. 不要给整张卡片或整页加 `data-small` 来躲检查。

### 出现滚动条（scrollbar）

- **报告里长这样**（整份课件）：`页面比窗口宽 120px，出现了滚动条`
- **原因**：页面里有东西撑出了窗口。常见的是页面 CSS 用了 `100vw`、`100vh`，或者给元素写了很大的宽高、负的 margin。
- **怎么改**：找到页面 CSS 里用 `vw`、`vh` 的地方，改成舞台像素（比如 `width:1680px`）；位置一律用舞台坐标的 `left`、`top`、`width`。

### 退回第 0 拍后没收干净（not-cleared）

- **报告里长这样**：`退回第 0 拍后，第 1 拍的「这一段字」还看得见`，或 `退回第 0 拍后，「……」还在（第一次进这一页时没有）`
- **原因**：自检会一拍拍走到最后、再一拍拍退回第 0 拍。退回来后还留着的东西，多半是 `onBeat` 前进时加了东西（类名、样式、元素），后退时没收回。
- **怎么改**：
  1. 找这一页的 `onBeat`。按 authoring.md 第 9 节的写法：后退、跳页、`Deck.motion` 为假时走「直接摆好」那条路，把 n 较小时该有的样子摆回去（比如 `classList.toggle('x', n >= 2)` 而不是只 `add`）。
  2. 能用 CSS 的 `.b2` 类写的效果，改用 CSS，前进后退自动对。
  3. 没写 `onBeat` 也报：检查是不是有元素写了一直显示的样式（比如自己写的 `visibility:visible`、`opacity:1 !important`），把它删掉，让 `data-beat` 来管显隐。

### 控制台报错（console-error）、页面出错（page-error）

- **报告里长这样**：`控制台报错：ReferenceError: foo is not defined`；`第 2 拍的 onBeat 出错：…`；`建这一页时组件初始化出错：…`
- **原因**：页面脚本出错了，或者有文件加载失败（`加载失败：…`）。
- **怎么改**：
  1. 照报错信息改。`onBeat` 出错：看是不是 `el.querySelector` 没找到元素（类名写错），先判断再用。
  2. `加载失败：slides/ch2.js` 这类：文件名或路径写错了，对照 `index.html` 的引入行。
  3. 先跑一次不开浏览器的 `check`，它会报出语法错误的文件和行号。
  4. `课件加载完 20 秒了，引擎还没开始自检`：多半是某个章节文件报错让引擎没能启动，先跑 `check` 找出那个文件。

### 引擎提醒（deck-warn，提醒）

- **报告里长这样**：引擎原话，比如 `页面 p05：主题太长，缩到最小还是放不下，请改短：…`
- **怎么改**：照提醒里的说明改；确实不用改的，跟用户说明为什么。常见的几条：

| 提醒里写的 | 怎么改 |
|---|---|
| `主题太长，缩到最小还是放不下` | 把 `topic` 改短，十五个字以内 |
| `data-in="x" 不认识，可选：…` | 换成可选里的名字，或者干脆删掉 `data-in` 用风格默认 |
| `风格「x」没有注册，先按朴素样子显示` | `scene` 写错了，或者这个风格没引入；换成已引入的风格 |
| `notes 里有第 n 拍，可页面上最多只到第 m 拍` | 讲词多写了拍，或者页面少写了一拍，照讲稿改 |
| `data-beat="x" 不是 0 以上的整数` | `data-beat` 只写 0、1、2 这样的整数 |
| `data-mark="x" 不认识` | 只用 circle、box、underline、strike、cross |
| `署名放在右下、左下、正下都会压住…` | 最后一页底部留出约 90px（y 990 以下别放字），形象也别站到底部；黑板的署名放在粉笔槽上面（y 950 左右），那一条也要空出来 |
| `风格混用了不同的家` | 同 `check` 的这条提醒，见上一节 |
| `页面 x：没写 title` / `第 n 页没写 id` | 同 `check` 的对应几条 |

### 图片、视频加载失败（media-missing）

- **报告里长这样**：`截图加载失败：素材/设置页.png`、`截图位没写图片地址（data-src）`、`图片加载失败：…`、`视频加载失败：…`
- **原因**：文件不在、路径写错（大小写、扩展名、中英文标点）、文件不在课件目录里。
- **怎么改**：检查文件名和路径，文件要放在课件目录里（比如 `素材/`），路径相对 `index.html` 写。用户还没给截图时，先告诉用户缺哪张，不要随便换一张图。

### 手机竖屏下太宽（reading-overflow）

- **报告里长这样**：`竖屏阅读模式下这一页比屏幕宽 80px（可用宽 370，内容宽 450）`
- **原因**：竖屏阅读模式下每页按屏幕宽度缩小显示；页面里有写死的、超出舞台的宽度，或者页面 CSS 改了页面外层的大小。
- **怎么改**：检查这一页 CSS 里写死的宽度（尤其是 `vw`、超过 1920 的宽度、负 margin），改成舞台坐标内的像素值；不要改 `.slide`、`.r-item` 这类引擎的外层元素。

### 这个尺寸没跑完（selftest-failed）

- **报告里长这样**（整份课件）：`… → 课件在这个尺寸下没跑完：先用 check 看有没有运行出错，改好后重跑 check --browser`
- **怎么改**：先跑不开浏览器的 `check`，把「运行出错」之类的错误改掉，再重跑 `check --browser`。还是不行，把报告原样告诉用户。

---

## 5. 改不动的时候

- 同一条改了三次还在：换个思路，删字、拆页，比一点点挪位置管用。拆页要同步改讲稿，并告诉用户。
- 报告看不懂、或者怀疑是误报：不要硬改别的地方，把这一条原样告诉用户，说明你试过什么。
- 环境问题（退出码 2，比如「没找到 Edge 或 Chrome」）：照提示处理，可以请用户装一个 Chrome，或用环境变量 `LI_TALK_BROWSER` 指定浏览器路径。浏览器自检跑不了时，不要说「检查都过了」，要跟用户说明只跑了不开浏览器的检查。

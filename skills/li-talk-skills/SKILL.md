# li-talk-skills：做一份一拍一拍翻的网页课件

## 先做这件事：运行 guide

**每次开工、每次换对话、每做完一步，都先运行 `guide`，照它的输出做。** 不要凭记忆判断做到哪了：`guide` 会读课件目录里的实际文件（讲稿.md、.li-talk.json、页面、上次自检的结果），告诉你现在在哪一步、下一步做什么。中途换了对话、换了模型，也能从这里接着做。

```
node "<本 skill 目录>/scripts/li-talk.mjs" guide "<课件目录>"
```

- **本 skill 目录**就是这份 SKILL.md 所在的目录。比如 skill 装在 `~/.claude/skills/li-talk-skills/`，就把 `<本 skill 目录>` 换成这个目录的完整路径（`~` 要写成真实的用户目录：引号里的 `~` 终端不认）。下文所有命令都写成 `node "<本 skill 目录>/scripts/li-talk.mjs" <命令>`。
- **课件目录**是放这份课件的文件夹（里面会有 `讲稿.md`、`index.html`）。还没有时，先对打算放课件的目录运行 `guide`（不写目录就是当前目录），它会建议一个目录名。
- `guide` 输出里的命令已经填好了完整路径（正斜杠，各种终端都认），**直接复制运行**，不要自己改写。

`guide` 每次都输出四块，各自这样用：

| 块 | 怎么用 |
|---|---|
| 【现在在哪一步】 | 九步里的第几步，以及课件的现状。读一下，心里有数 |
| 【下一步做什么】 | 一条条照做，命令原样复制运行 |
| 【问用户】 | 里面的问题**原样转给用户**：工具里有选项卡片（比如 Claude Code 的提问卡片）就用卡片，**一次问一个**，推荐项放第一个；没有卡片就把问题和编号选项原样发给用户，请用户回一个数字或直接说。问题上方括号里写了什么时候问（比如「提纲写好以后问」），就到那时再问。用户回答之前不往下做 |
| 【可以这样对 AI 说】 | 给**用户**看的回话示例，告诉用户可以怎么回你。不是给你执行的命令 |

做完【下一步做什么】里的事，再运行一次 `guide`，看下一步。

## 这一版能做什么（最小可用版）

这是最小可用版，只承诺下面这些：

- **6 种风格**：方格纸 `paper`、黑板 `board`、像素手账 `journal`、工位桌面 `desk`、水彩田园 `watercolor`（这五种是手绘家），科技暗黑 `dark`（现代家）。
- **2 个形象**：朵朵 `duoduo`（手绘家几种风格默认用它）、微光 `weiguang`（科技暗黑默认用它）。
- **4 种样板页**：封面、清单、步骤（图示）、结尾，写在 `references/templates.md`。
- **课件本身**：按拍出现、讲过的拍变淡、主题行、重点词、圈注、手绘线和箭头、卡片、步骤、对比、终端窗口、点击复制、截图位（点开看大图）、形象每拍走到内容旁、演讲者视图（S）、计时（T / R）、全屏（F）、竖屏阅读模式、刷新不丢位置、最后一页自动署名。双击 `index.html` 离线打开。
- **检查**：不开浏览器的检查 `check`，后台浏览器自检 `check --browser`（5 个尺寸逐页逐拍量，出中文报告）。

**还没有的，不要承诺给用户**，也不要自己往课件里加：总览跳页、黑屏、激光笔、屏幕画笔、彩排模式、快捷键帮助、进度条；新组件（代码逐行点亮、前后对比滑块、视频演示、图表、展开详情、大图缩放拖动）；打包（`pack`）、升级和自动更新；形象工坊和用户自己的形象；其余风格。用户问到时，直接说「这一版还没有」。导出 pptx 或 pdf 不在这个 skill 的范围里。

## 九步流程和五处停下

| 步 | 做什么 | 停下等用户？ | 用户明确说可以后运行 |
|---|---|---|---|
| ① 起点 | 问用户手上有什么，建课件目录和 `素材/`，有材料就运行 `materials` | | |
| ② 提纲 | 问场合（讲给谁、多久、什么场合和屏幕、想让听众带走什么），把提纲写在 `讲稿.md` 开头 | **停下** | `confirm <课件目录> outline` |
| ③ 讲稿 | 照 `references/script-format.md` 一页页写讲稿 | **停下** | `confirm <课件目录> script` |
| ④ 风格 | 运行 `styles` 推荐、`styles --open` 打开样册，用户选 | **停下** | `confirm <课件目录> style --scenes <键名>` |
| ⑤ 搭骨架 | 运行 `new` | | |
| ⑥ 先做 3 页 | 封面加讲稿里最典型的两页（一页图示、一页清单），自检清零后打开给用户看 | **停下** | `confirm <课件目录> trial` |
| ⑦ 写全稿 | 照讲稿写完剩下的页，自检清零 | | |
| ⑧ 过稿 | 打开整份课件给用户看，按意见改，改完重新自检清零 | **停下** | `confirm <课件目录> review` |
| ⑨ 完成 | 告诉用户怎么讲 | | |

**为什么要停下**：后面的每一步都建立在前面的上面。提纲不对，讲稿白写；讲稿不对，页面整页重写；风格不对，3 页试做白做。在这五处让用户点头，返工最少。

停下的规矩：

- **「明确说可以」** 是用户说了「可以」「行」「就这样」「没问题」这类话。用户没回、说「先这样吧我再看看」、只改了一个小地方，都不算确认：改完再问一次。
- **一次只确认一处。** 不要一口气把提纲、讲稿都 `confirm` 了。没确认的那一步，不往下做。
- **确认之后马上运行 `confirm`**，再运行 `guide`。`guide` 靠这些记录判断进度，忘了记，下次就会回到老地方。
- 用户说「你直接做完吧，不用问我」：照用户说的少问，但这五处仍然把成果给用户看一眼，用户说可以再 `confirm`。

## 命令一览

所有命令前面都是 `node "<本 skill 目录>/scripts/li-talk.mjs"`。

| 命令 | 做什么 |
|---|---|
| `guide [课件目录]` | 看做到哪一步、下一步做什么、该问用户什么。不写目录就看当前目录 |
| `materials <素材目录>` | 列素材清单：文字（字数）、图片（尺寸）、视频（大小）；有图片时生成 `截图说明.md` |
| `styles` | 列出所有风格：样子、适合、不适合、要注意的、默认形象，按家分组 |
| `styles --open` | 用浏览器打开样册，看样板页在各种风格下的样子（样册没做好时会说明） |
| `confirm <课件目录> <环节>` | 记下用户已确认的环节：`outline` 提纲、`script` 讲稿、`style` 风格、`trial` 3 页试做、`review` 过稿 |
| `confirm <课件目录> style --scenes a,b [--mascot 形象]` | 确认风格时顺带记下风格和形象 |
| `new <课件目录> --title 标题 --scenes 风格[,风格] [--mascot 形象]` | 搭骨架：复制引擎、选中的风格和形象、字体，生成 `index.html` 和一页封面 `slides/ch1.js` |
| `open <课件目录>` | 用系统浏览器打开课件 |
| `check <课件目录>` | 不开浏览器的检查，几秒出结果 |
| `check <课件目录> --browser` | 后台浏览器自检，5 个尺寸逐页逐拍量一遍，出中文报告 |
| `check … --browser --pages 3-5` | 只查几页（快，但最后要完整跑一次） |
| `check … --browser --shots` | 另外给每页最后一拍截图，存在 `<课件目录>/.li-talk/shots/` |
| `check … --browser --scene 风格` | 临时换成某种已引入的风格来自检（不更新自检记录） |
| `fonts` | 下载或检查本机的完整字体（`new` 会自动做，一般不用管） |
| `fonts --into <课件目录>` | 课件用的是小字库时，下载好完整字体后装进这份课件 |
| `version` | 查看版本 |

退出码：0 没问题；1 有错误（报告里写了）；2 环境问题（比如 Node 版本太低、找不到浏览器）。

## 写页面的规矩

写页面（⑥ 先做 3 页、⑦ 写全稿、⑧ 按意见改）时必须遵守：

1. **只改 `slides/` 和 `index.html` 里两对「章节」注释之间的行。** `engine/`、`scenes/`、`mascots/`、`vendor/` 和 `index.html` 的其他行不碰。唯一的例外是搭好骨架后换风格，照 `references/styles.md` 的「搭好骨架后换风格」做。
2. **先找最接近的样板照着改**（`references/templates.md`），不要从零写。样板在 6 种风格下都调好了，照着改最不容易出错。抄过来以后，样板的 `id`、`scene` 和 CSS 里的 `[data-id="…"]` 都要换成这份课件的（讲稿页号、选定的风格）。
3. **页面 id 用讲稿页号**：讲稿第 5 页就是 `id: 'p05'`。先做 3 页时就这样写，写全稿时把中间的页按顺序补进去。
4. **屏幕上的字照讲稿「屏幕」一段原样写**，拍数照「节拍」，讲词照「讲词」写进 `notes`。
5. **新增一章**：建 `slides/ch2.js` 和 `slides/ch2.css`，并在 `index.html` 两对「章节」注释之间各加一行引入（`references/authoring.md` 第 1 节有改完的样子）。
6. **守住技术边界**：只用普通 `<script src>` 和课件目录里的本地文件，不用 `import`、`fetch`、ES module、CDN、网络字体、外链图片、框架。原因和改法见 `references/authoring.md` 的「技术边界」一节。
7. **写完必须跑两种检查**：每写完一章跑 `check <课件目录>`；写完一批跑 `check <课件目录> --browser`。**错误清零才给用户看。** 提醒逐条判断：要么改，要么跟用户说明为什么不改。
8. **改了页面就要重跑自检。** `guide` 会比较页面和上次自检的时间，页面改过而没重跑，它不会让你往下走。

### 看不了图怎么办

看不了图的模型，**靠自检报告改，不要猜**。报告替你「看效果」：每条都写了在第几页第几拍、在哪个尺寸、什么问题、量到的数字、怎么改。照数字改：「超出卡片底边 46px」就删字或去掉固定高度；「形象的身子压住了…（交叠约 134×6px）」就在目标元素上加 `data-mascot-dy="24"` 或换一侧。每类问题的详细改法在 `references/checklist.md`。

能看图的模型，可以加 `--shots` 让脚本给每页最后一拍截一张 1920×1080 的图（`<课件目录>/.li-talk/shots/p01.png` 这样），打开看有没有挤成一团、颜色是否协调。截图只是补充：报告里的错误照样必须清零。

都在本 skill 目录的 `references/` 下：

| 什么时候 | 读哪份 |
|---|---|
| ③ 写讲稿之前；整理用户已有的讲稿时 | `script-format.md`：讲稿的提纲、四段格式、规则和两页完整示例 |
| ④ 推荐风格、用户想换风格时 | `styles.md`：6 种风格的样子、适合、脾气、禁区，按章分配，搭好骨架后换风格 |

## 课件目录长这样

```
我的分享/
  讲稿.md          讲稿：开头是提纲，后面每页四段
  素材/            用户的材料和截图（截图说明.md 也在这里）
  index.html       入口，双击就能打开；只改两对「章节」注释之间的行
  slides/          章节文件：ch1.js、ch1.css、ch2.js、ch2.css……（写页面只改这里）
  engine/          引擎（不改）
  scenes/          这份课件用到的风格（不改）
  mascots/         这份课件用的形象（不改）
  vendor/          动画库、手绘线库、字体（不改）
  .li-talk.json    进度记录：确认过哪些环节、用了哪些风格（由 confirm 和 new 写，不手改）
  .li-talk/        自检记录和截图（由 check 写）
```

## 常见情况

- **用户中途回来、换了对话或模型**：先运行 `guide <课件目录>`，照它说的接着做。不知道课件目录在哪，就问用户，或者对上一级目录运行 `guide`，它会列出那里已有的课件。
- **用户有材料（笔记、截图、文档）**：复制进 `素材/`（原文件别动、别删），运行 `materials <课件目录>/素材`。Word、PDF 这类读不了的，请用户导出成文字。截图的用途：能看图就自己看图填 `截图说明.md`，看不了图就请用户每张填一句「这是什么、放在讲哪块的时候用」。提醒用户：课件里的截图点开显示的是原图，敏感信息也会被看到。
- **用户想看换个风格的样子**：先 `styles --open` 打开样册比较；地址栏加 `?scene=键名` 只对这份课件里已经引入的风格有效。定了要换，照 `references/styles.md` 的「搭好骨架后换风格」做。
- **讲稿要改**（拆页、合页、改字）：先改 `讲稿.md`，再改页面，两边保持一致；改动大的话请用户再看一眼。
- **课件用的是小字库**（`new` 时完整字体没下载成功）：不影响往下做，个别生僻字会用系统楷体。之后网络好了运行 `fonts --into <课件目录>` 换成完整字体。
- **找不到浏览器**（`check --browser` 退出码 2）：照提示请用户装 Chrome，或用环境变量 `LI_TALK_BROWSER` 指定浏览器路径。没跑成浏览器自检时，不要说「检查都过了」。
- **交付时**（⑨ 完成）：告诉用户怎么讲：→ ↓ 空格 PageDown Enter 或点击下一拍，← ↑ PageUp 上一拍，Home / End 第一页 / 最后一页，S 演讲者视图（另开窗口看讲词），T 计时开始或暂停，R 计时归零，F 全屏。发给别人时把整个课件目录拷走（或压缩成 zip），对方双击 `index.html` 就能看。

## 不要做的事

- 不要跳过 `guide` 凭记忆往下做；不要在用户没明确确认时运行 `confirm`。
- 不要改 `engine/`、`scenes/`、`mascots/`、`vendor/`，不要改 `index.html` 章节区以外的行（换风格时的风格引入行除外）。
- 不要在自检还有错误时把课件给用户看，也不要说「应该没问题」。
- 不要编造讲稿里没有依据的数字、百分比、案例、用户反馈。
- 不要承诺这一版还没有的功能（见「这一版能做什么」）。
- 不要把用户的材料、截图上传到任何地方；课件和素材只留在用户本机的课件目录里。

# li-talk-skills 设计文档

> 状态：下文是整体设计，并非都已做完。0.1.0 已实现的部分见 [CHANGELOG](../CHANGELOG.md)，还没做的见 [roadmap](roadmap.md)。写于 2026-11-17。
> 这份文档讲清 li-talk-skills 做成什么样、守哪些规矩、按什么顺序做、怎么验证。实施计划另写。

## 0. 一句话

li-talk-skills（中文名「演讲课件」）是一个给 AI 编程工具用的 skill。AI 照它的流程和规矩，把讲者的主题、想法、笔记和截图做成一份 HTML 演讲课件：像幻灯片一样一拍一拍地翻，双击就能离线打开，带演讲者视图、计时、动效，每种风格还有自己的小形象。

## 1. 目标与范围

### 1.1 要做到

- **各种模型都能用**：Claude、GPT、DeepSeek 等模型都要能用，工具可以是 Claude Code、Codex、Cursor 这类能跑命令、能写文件的 AI 编程工具。下限比上限重要，做法见第 2 节。
- **引导到位**：不知道怎么做的用户，一问一答带着走；已经写了想法、放了截图的用户，从他的材料出发，只问缺的。
- **风格**：内置 15 种风格。AI 按内容推荐，用户看样册自己选定。
- **讲得好用**：按拍出现、演讲者视图、计时、彩排、总览跳页、黑屏、激光笔、屏幕画笔等。
- **屏幕**：最大按 1920×1080 设计，向下覆盖笔记本、平板和手机。
- **自动更新**：每天第一次运行时检查新版本，带更新说明（CHANGELOG）和图文 README。

### 1.2 适用环境

- AI 工具：能执行命令、读写本地文件的 AI 编程工具。网页版聊天框不在范围内。
- 本机：Node 18 及以上。
- 浏览器：Chrome、Edge 上所有功能正常；Safari、Firefox 能正常看，少数效果会降级，比如液态玻璃的折射。

### 1.3 不做

- 不导出 pptx、pdf，不做打印讲义。
- 不做资源页二维码。
- 不做在线托管、多人同时编辑。
- 公开仓库里不带任何真实分享的内容和截图。

## 2. 守住下限的思路

页面仍由 AI 手写，用 `Deck.add` 一页一页写 HTML。现在的模型写基础 HTML 没有问题，难的是写完不知道效果对不对：看不了图的模型发现不了溢出、重叠、形象挡字。所以下限靠下面三样来兜：

1. **样板页**：约 15 种常见版式的样板，每种在所有内置风格下都调好了。AI 先找最接近的样板照着改，少从零写。
2. **不开浏览器的检查**（`check`）：查写法错误、越界的技术用法、拍数和讲词对不上等，几秒出结果。
3. **后台浏览器自检**（`check --browser`）：用本机浏览器在后台逐页逐拍、按 5 个尺寸量一遍，出一份中文的文字报告。每条写明在哪、什么问题、量到的数字、怎么改。替看不了图的模型「看效果」。

另外三条规矩配合：技术栈的边界写死（第 3 节）；谁能改哪些文件写死；流程里有五处必须停下来等用户确认（第 4 节）。

## 3. 技术栈边界

### 3.1 课件这一端

一份课件就是一个文件夹，双击 `index.html` 就能离线打开（`file://`）。

| | 能用 | 不能用 |
|---|---|---|
| 加载方式 | 普通 `<script src>`、`<link>`，按顺序引入 | ES module、`import`、`fetch` 本地文件、CDN、网络字体、外链图片 |
| 写法 | 原生 JS；CSS 变量、flex、grid；内联 SVG 和 SVG 滤镜 | npm、构建工具、React / Vue / Tailwind 这类框架 |
| 库 | 只有 `vendor/` 里的：gsap 3（动画）、rough.js（手绘线）、霞鹜文楷、缝合像素字体 | 其他第三方库；canvas 或 WebGL 大场景 |
| 媒体 | 本地图片、本地视频和动图（点击播放） | 外链媒体 |
| 画面 | 舞台 1920×1080，按窗口等比缩放；正文不小于 34px | |

激光笔（0.1.0 已做）和屏幕画笔各用一层透明的 canvas 覆盖层。它只是一层很小的绘图层，不算「canvas 大场景」。

### 3.2 谁能改哪些文件

- 写页面的 AI 只改 `slides/` 里自己负责的 `<章>.js` 和 `<章>.css`。页面 CSS 一律以 `[data-id="…"]` 开头，不碰引擎、风格和形象文件。
- 风格、形象、引擎只由 skill 内置。使用的人只管选，不管造。想加新风格的，照 `references/add-style.md` 做。

### 3.3 脚本这一端

- 只要求 Node 18 及以上，只用 Node 自带的模块，不装任何 npm 包。Windows、macOS、Linux 都能跑。
- 所有命令都从一个入口进：`node "<skill 目录>/scripts/li-talk.mjs" <命令>`，命令见第 10 节。

## 4. 引导和做课件的流程

### 4.1 先问「你手上现在有什么」，按起点分三条路

1. **只有一个主题，不知道怎么做**：一问一答，问讲给谁、讲多久、在什么场合和屏幕上讲、最想让听众带走什么。AI 据此起一份提纲（分几部分、每部分几页），给用户改，定了再写讲稿。
2. **有想法、笔记、截图**：材料放进课件目录的 `素材/`，或者直接告诉 AI 在哪。`materials` 命令先列一份素材清单，分文字和图片，图片带尺寸。AI 读完文字材料整理成提纲，标出哪部分材料够了、哪部分缺内容，只问缺的。现成的文档、在线文档链接也当素材用；AI 读不了的格式，请用户导出成文字。
3. **已经有讲稿**：AI 把它整理成标准的四段格式（见 4.6），补上缺的段落，给用户确认。

### 4.2 截图要照顾看不了图的模型

- `materials` 生成一份截图说明表。能看图的模型自己看图，每张写一句说明；看不了图的模型，请用户每张填一句「这是什么、放在讲哪块的时候用」。
- 提醒用户：课件里的截图点开显示的是原图，页面上只露一部分时，原图里的敏感信息也会被看到。

### 4.3 固定流程

① 场合与提纲 → ② 讲稿 → ③ 推荐并选定风格 → ④ 搭骨架 → ⑤ 先做 3 页 → ⑥ 写全稿 → ⑦ 自检清零 → ⑧ 用户过稿、按意见改 → ⑨ 打包交付

- **推荐风格**：按每部分讲什么查风格表，给一个主推加理由，同时打开样册给用户看。样册里所有风格都能选，用户说了算。内容跨度大时，可以建议按章分配，最多 3 种，并且只在同一类里混（见 6.3）。
- **先做 3 页**：风格选定后，先做封面加内容最典型的两页（一页图示、一页清单），自检清零后给用户看。用户提完意见、确认可行，再写全稿。用户想看换个风格的样子时，地址加 `?scene=<风格>` 当场就能看，不用重做（见 6.4）。
- **必须停下等用户确认的五处**：提纲、讲稿、风格、3 页试做、过稿。没确认不往下做。
- **交付时**告诉用户怎么讲：翻页键、演讲者视图、计时、总览跳页、黑屏、激光笔，并提醒正式讲之前先在演讲者视图里按 H 彩排一遍，把小结复制给 AI，让它删减超时页的讲词。快捷键帮助（按 `?`）还没做，做好以前不跟用户提。

### 4.4 提问方式

- 工具里有选项卡片（比如 Claude Code 的提问卡片）就用卡片，一次问一个问题，标出推荐项。
- 没有卡片的工具，改用编号选项，用户回一个数字即可。
- `guide` 输出的每个问题都带好选项，方便直接做成卡片。

### 4.5 `guide` 命令

每次运行都检查课件目录的实际状态，告诉 AI 现在在哪一步、下一步做什么、该问用户什么，并给出「你可以这样对 AI 说」的例子。进度从文件本身推断：讲稿写到哪了、讲稿开头记的风格、写了几页、上次自检的结果。所以中途换对话、换模型也能接着做。刚装好时，`guide` 顺带检查 Node 版本、字体缓存和更新。

**新手教程**：本机还没有 `~/.li-talk-skills/tour.json` 时，`guide` 在 ① 起点把「要不要先过一遍新手教程」放在问题 1。用户选看，AI 运行 `tour`：用浏览器打开 `template/tour/index.html`（一份用方果风格做的 20 多页课件，讲这个工具怎么用；同一份用 pages.mjs 打包后托管在 GitHub Pages），用户看完再 `styles --open` 打开样册过一遍全部风格。必须由 AI 运行命令打开，不把路径丢给用户自己开；打不开浏览器时才给路径。用户选不看，运行 `tour --skip`。两种都记进 tour.json，之后不再问；打不开浏览器时不记，下次还会问。教程课件和样册一样直接引用模板里的引擎、风格和形象，不复制。

### 4.6 讲稿格式

讲稿是课件目录里的 `讲稿.md`。文件开头可以有一页「给组织方」的简介：一句话简介、适合谁听、大纲、听完能带走什么、时间与时长。之后每页四段：

```
## 第 N 页 页标题

章节标记：……　风格：……
主题：章节短名 › 本页主题

**屏幕**（投出来的字，原样使用）
- 主题行：章节短名 › 本页主题
- 标题：……
- 一句话解释：……（新概念第一次出现的页才有）
- ……（点击复制的内容写成一行代码，后面注明「（点击复制）」）

**节拍**
- 第 0 拍：翻到这页就在的内容｜重点词：xx
- 第 1 拍：出现什么｜重点词：xx

**画面**（怎么画、怎么动、形象做什么；要用截图的写明用哪张）

**讲词**（照着讲，不投出来；按拍分段，重点词加粗）
【第 0 拍】……
【第 1 拍】……
```

规则和原因写进 `references/script-format.md`，要点：

- 每页 2 到 4 拍（封面结尾 1 到 2 拍）。讲一拍按一下，讲者才知道这页要点几下、讲到哪了，动效也才有人看到。
- 每页顶部一行主题。大标题常常是一句论点，翻到这页的人需要知道在讲什么。
- 新概念第一次出现的那页，第 0 拍先用一句大白话解释。
- 每拍一个重点词，讲词里加粗，屏幕上有这个词就标出来。
- 屏幕上的字短而具体；讲词用第一人称、短句，每拍三四句以内。
- 不写没有依据的数字、百分比、案例和用户反馈。
- 用总字数控制时长，按每分钟 220 到 250 字估。到了上限再加内容，必须从别处减。

## 5. 课件功能

### 5.1 基础功能

1. **按拍出现**：点击、空格、→、↓、PageDown、Enter 进一拍，本页拍完进下一页；←、↑、PageUp 退一拍；Home、End 跳到首尾。连按时正在播的动画直接跳到结尾，不排队。单拍的内容动效总时长压在约 1.2 秒内。
2. **讲过的拍自动变淡**：之前的内容变淡，当前拍始终最显眼；鼠标移上去亮回来；可以按元素或整页关掉。
3. **主题行**：每页左上「章节短名 › 本页主题」，第 0 拍就在，不参与节拍；放不下时自动缩字，不换行。
4. **一句话解释**（`.explain`）：大标题下面一行。
5. **重点词**（`<em class="key">`）：每种风格有自己的强调方式和到拍动画。
6. **圈注**（`data-mark`）：圈、框、下划线、删除线、叉，可以晚几拍再圈。
7. **出场方式**（`data-in`）：上浮、淡入、弹出、落下、滑入、写出、打字、描线、盖章、打印等；可设延迟和逐个出现；不写时按风格的默认出场。
8. **手绘线稿**：`svg.sketch` 里的图元由 rough.js 画成手绘线，按笔画描出。
9. **形象**：每拍可以走到指定元素旁，见第 7 节。
10. **点击复制**（`data-copy`）：「已复制」反馈每种风格不同，自动找不压字的位置；点它不进拍。
11. **截图位**：可以只露出原图的一块，点开看完整大图，Esc 关闭。
12. **散落再归位**：一组元素先散落，到指定拍飞回排好的位置，退拍再散开。
13. **自定义动画**：`onBeat(n, el, dir)` 返回一段 gsap 时间线。
14. **转场**：换风格时新背景擦入；同风格翻页各有各的方式。
15. **节拍指示与页码**：在右上角，每种风格样子不同、位置一致；换拍时有一个小动效。
16. **演讲者视图**：按 S 打开独立窗口，显示主题行、标题、本页每拍的讲词，当前拍高亮，底部预告下一拍；在这个窗口里按翻页键同样有效，按 O、B、L 也同样控制主窗口；T 开始或暂停计时，R 计时归零。演讲者视图里按 H（或点「开始彩排」）进入彩排，再按 H 结束，见 5.2。
17. **竖屏阅读模式**：手机和平板竖屏自动切换，页面竖排、上下滑，所有拍直接展开；地址带 `?read` 可以强制进入，带 `?notes=1` 显示讲词。
18. **刷新不丢位置**：地址形如 `#页/拍`，也支持 `#页面id`。
19. **减少动态**：尊重系统的「减少动态」设置，开启后内容直接显示，没有视差和形象的空闲动作。
20. **F 全屏**。
21. **写错提示**：控制台里以 `[Deck]` 开头的提示，比如 id 重复、风格写错、讲词拍数对不上。
22. **非当前页不接收点击**。

### 5.2 新增功能

| 组 | 功能 |
|---|---|
| 讲者用 | **总览跳页**（O）：所有页的缩略图，点一页或输入页码回车即可跳过去；←→↑↓ 选、回车跳，Esc 或再按 O 关闭。缩略图是每页摆到最后一拍的样子；跳过去落在那页的第 0 拍，不播翻页动画。（0.1.0 已做） |
| | **黑屏**（B，也认很多翻页笔黑屏键发的「.」）：一键全黑，再按 B、Esc、任意翻页键或点一下恢复，恢复时不翻页。**激光笔**（L）：鼠标变成红点，带一小段拖尾，开着时点击照常进拍，Esc 也能关。演讲者窗口里按 O、B、L 同样控制主窗口。（0.1.0 已做） |
| | **屏幕画笔**（D）：在当前页上画，翻页时清掉 |

| | **快捷键帮助**（?） |
| 观众看 | **进度条**：舞台底边一条细进度条，按全稿拍数走、按章节（`chapter` 变化处）标出分段点；第 0 拍就在，不进拍，不用设置；颜色取风格的墨色和强调色；阅读模式不显示。（0.1.0 已做） |
| | **目录页、章节页**：做成样板页 |
| 内容交互 | **代码讲解**：代码块按拍逐行点亮；自带一个轻量的语法高亮，覆盖常见语言，不引第三方库 |
| | **前后对比滑块**：拖动中间的分隔线看前后两张图 |
| | **本地视频和动图**：点击播放，不算进拍 |
| | **图表**：柱状、折线、环形，用 SVG 画，按拍长出来 |
| 细节 | **大图缩放拖动**、**外链在新窗口打开**、**展开详情** |
| | 平板和手机上左右滑动翻页；点屏幕右侧前进、左侧后退 |

**点击规则**：点页面空白和普通内容（包括卡片）进一拍，卡片可以有按压反馈；命令、形象、链接、视频、可放大的图、滑块、展开详情这类明确可交互的元素，点了不进拍。

### 5.4 署名

课件的最后一页，由引擎自动加上一行署名：「由 小黎 · li-talk-skills 提供支持」，点一下复制 GitHub 仓库链接（链接不显示在屏幕上，鼠标停上去能看到）。署名的样子跟着风格走，位置自动避开内容。不提供关闭的开关。

## 6. 引擎与风格体系

### 6.1 页面写法

```js
Deck.add({
  id: 'p10',                  // 必填，全稿唯一；页面 CSS 以 [data-id="p10"] 开头
  chapter: '二、上手',         // 章节名
  chapterShort: '上手',        // 可选；不写时自动去掉「一、」这类序号
  topic: '三步做出一份课件',     // 本页主题，封面结尾可以不写
  scene: 'paper',             // 风格的键名，见 6.5
  title: '一份课件，三步做完',   // 必填，纯文字，引擎画成大标题
  titleHtml: '…',             // 可选，标题里要放重点词时用
  noTitle: false,             // 可选，封面用
  recede: true,               // 可选，false 时整页关掉自动变淡
  html: `…`,                  // 用 data-beat="n" 标每块属于第几拍
  notes: [{ beat: 1, key: '讲稿', show: '写讲稿', say: '…' }],
  onBeat(n, el, dir) { return gsap.timeline() }   // dir：1 前进，-1 后退，0 直接跳到
})
```

- 拍数由引擎从页面里最大的 `data-beat` 算出来。
- 通用组件：卡片或便签、带序号的步骤、左右对比、一排小格、终端窗口、可复制的一行、手绘箭头与连线、圈注、截图位、大字金句、标签，以及 5.2 新增的代码块、对比滑块、视频、图表、展开详情。
- 全稿统一的约定：一页一个视觉重心；每页 2 到 4 拍；正文不小于 34px；每页有主题行；新概念第一次出现时第 0 拍先有一句解释。

### 6.2 风格可插拔

引擎里不出现任何风格名。每种风格是 `scenes/` 下的一组文件（`<键名>.css` 和 `<键名>.js`），用 `Deck.scene()` 注册：

```js
Deck.scene('ink', {
  label: '水墨国风',            // 给人看的名字
  family: 'hand',             // 属于哪一类，见 6.3
  dark: false,                // 深色底时为 true：形象加浅色描边，主题行等用浅色
  enter: 'write',             // 不写 data-in 时的默认出场
  recede: .8,                 // 讲过的拍变到多淡：不低于 .75（低了引擎提醒并按 .75），讲过的字仍要看得清
  mascot: 'mowan',            // 这种风格默认用的形象，见第 7 节
  decorate(slideEl) {},       // 每页建好后加装饰
  intro(ctx) {},              // 开场
  onBack(ctx) {},             // 退一拍时的额外动作
  pageTurn(ctx) {},           // 同风格翻页的方式；不写就用默认的平移
  copied(ctx) {},             // 「已复制」反馈
  defs: '<filter …>'          // 需要的 SVG 滤镜
})
```

字段名以实现为准，上面是最小集合。

**每种风格必须实现的清单**：

- 全套 CSS 变量，所有风格共用同一套变量名和组件类名，所以页面换风格不用改结构；
- 每个通用组件的样子；
- 主题行、节拍指示（含换拍小动效）、页码；
- 重点词的强调和到拍动画、圈注的画法；
- 默认出场方式，每拍的出场是一小段有先后的编排；
- 讲过的拍变到多淡；
- 复制反馈；
- 同风格翻页方式（可以先用默认的平移）；
- 页面装饰、需要的 SVG 滤镜；
- 开场：不带 `#拍号` 打开时约 1 秒的开场，带拍号直接摆好；
- 悬停反馈：卡片、步骤、命令在鼠标移上去时有这种风格自己的反馈，移开复原；
- 点击反馈：在点击处出一个很淡的风格化涟漪；
- 背景视差（可选）：位移不超过十几像素；
- 深色底上形象的描边；
- 结尾署名的样子。

**动效的硬规矩**：

- 不允许循环播放的动画。形象的眨眼、偶尔的小动作，以及走路时的迈步帧除外。
- 单拍的内容动效约 1.2 秒以内。形象的动作可以稍长一点，但连按时一律直接跳到结尾。
- 开启「减少动态」时：没有开场、没有视差、没有空闲动作，内容直接显示。
- 性能保护：引擎在前两次翻拍时测帧率，太低就自动关掉风格声明为「贵」的效果，比如折射、视差。

### 6.3 风格分三家

每种风格声明自己属于哪一类、用什么字体：

- **手绘风**（楷书）：方格纸、黑板、像素手账、工位桌面、水彩田园、水墨国风、蓝图、漫画。
- **现代风**（黑体，杂志复古用宋体）：科技暗黑、毛玻璃、液态玻璃、扁平插画、杂志复古、新粗野主义。
- **像素风**（中文像素字体）：像素游戏。它的字体和网格都自成一套，不和别的风格混用。

一份课件按章换风格时，只在同一类里换。`check` 发现跨类混用会报提醒。字体、强调色的用法、重点词的标法、节拍指示的位置、形象，必须全稿统一。

### 6.4 临时换风格

- 地址加 `?scene=<键名>`，整份课件临时全换成这个风格，比如 `?scene=ink`。
- 样册用这个功能：选一个风格，就能看到所有样板页在这个风格下的样子。
- 用户看完 3 页试做，也能用它当场比较别的风格。

### 6.6 样板页

约 15 种，每种都要在所有内置风格下好看：

| 开头结尾 | 讲内容 | 技术分享 | 演示 |
|---|---|---|---|
| 封面、目录、章节页、结尾 | 清单、对比、步骤、图示（组成或关系）、金句 | 命令清单（终端）、代码讲解（逐行点亮） | 截图讲解、前后对比滑块、视频演示、数据图表 |

样板页同时是样册的内容，用一个虚构的中性主题来写。

**现在的做法（2026-11-18 起）：样板分两套。**

- **每种风格自己的样板页**（`template/samples/<键名>.js`、`.css`）：作者看了初版样册，说 15 种风格只是换皮、版式一样。所以每种风格按自己的版式、结构和每拍的动作，把同一个虚构主题「怎么泡好一杯茶」做成 5–6 页，其中 1–2 页是招牌页（只有这种风格做得出来的版式，比如水墨的手卷、像素的关卡地图、蓝图的装配清单）。风格的专用组件写在风格文件里，类名带风格前缀，每拍的动作由组件完成，页面里只写结构和 `data-beat`。各风格的招牌页互不重复。
- **通用样板页**（`samples/samples.js`，4 页）：只用通用组件，哪种风格都能用；风格样板里找不到合适的版式时用它。
- **可读性底线**：作者看了第一版试点，说形态是对了但可读性变差了。所以自有版式也要守底线（`references/authoring.md` 第 0 节第 9 条）：讲过的要点留在页上、讲过的只退到 .8、句子横排、一条阅读顺序、装饰字效只给短标题、先说真话再包装、装饰不压字、强调要少。自检查其中三条：对比度、竖排、讲过的看不见了。
- **用在哪**：样册带 `?scene=` 时放这种风格自己的样板（`gallery.html` 的 `NATIVE` 列表）；`guide` 在 ⑥ ⑦ 让 AI 先读所选风格的样板照着写；每种风格的预览课件在 `test/fixtures/decks/native-<键名>/`，5 个尺寸 0 错误 0 提醒。
- **代价**：专用组件只在自己的风格里成立，换风格时用了它们的页要照新风格的样板重写，不能只改 `scene`。

### 6.7 引擎文件拆分

浏览器这边仍然用普通的 `<script src>` 按顺序引入。引擎按职责拆成多个文件，方便多人并行开发：核心（节拍、翻页、出场、地址）、形象、演讲者视图与彩排、现场工具（总览、黑屏、激光笔、画笔、帮助）、组件、自检模式。

现在的引入顺序：`core.js → build.js → beats.js → mascot.js → pages.js → ui.js → presenter.js → tools.js → selftest.js`。`tools.js`（总览、黑屏、激光笔、进度条）排在演讲者视图之后、自检之前；`index.html` 里少了这一行时 O、B、L 不起作用、没有进度条，别的照常；旧课件升级时要补上这一行，见 `docs/roadmap.md` 的升级一条。自检模式（`?selftest`）下 `tools.js` 整个不启用，彩排也不启用。

课件目录长这样：

```
我的分享/
  index.html        入口：按顺序引入 vendor、引擎、风格、形象、各章；记着引擎版本号
  讲稿.md
  素材/
  engine/           引擎各文件和 engine.css
  scenes/           用到的风格
  mascots/          用到的形象
  slides/           各章的 .js 和 .css
  vendor/           gsap、rough、字体、各自的许可证
  gallery.html      样册入口，可选
```

## 7. 形象

### 7.1 规格

- 每个形象是 `mascots/` 下的一个文件，用 `Deck.mascot('名字', {…})` 注册，提供 `svg(pose, opts)`，返回内联 SVG 字符串。像素风的形象用 `rect` 拼，注册时写 `pixel: true`，引擎把它落定的位置取整到整数屏幕像素，边缘不虚。
- 姿势至少四种：`idle` 平常、`point` 指向（另一侧用镜像）、`happy` 开心、`rest` 休息；另有眨眼（或这个形象等价的小动作）。可以另带过渡帧，比如腾空、下蹲、迈步、点头。
- 舞台上显示约 100–130px 高，轮廓清楚，在投影上一眼能看清；深色底上要有浅色描边或亮边。
- 必须原创，不能像已有的动画、游戏、品牌角色，也不能像任何 AI 产品的图标。

### 7.2 一份课件一个形象

- 全稿只用一个形象。按章换风格时，形象不跟着换。
- 默认用主风格的形象，也可以换成别的风格的形象，或者用户自己的形象。
- 页面里用 `data-mascot` 系列属性指定每拍走到哪个元素旁、站在哪一侧、用什么姿势、说什么气泡。旧写法 `data-kid` 系列继续认，效果和 `data-mascot` 相同，已有的课件不用改。

### 7.3 通用动作与规矩

- 每拍走或蹦到这一拍的内容旁，落地压一下，点头或指向；视线朝向当前内容。同一页里每拍的动作尽量不重复。
- 复制成功时变开心；鼠标移上去变开心；点它会有反应（轮换两三种），不进拍。
- 翻页时从上一页的位置过来。
- 不许挡字，气泡也不许压字。落点由自检量出来，挡字就报错。

### 7.4 空闲动作和打盹

- 空闲时每 8–15 秒随机做一个很小的动作，比如东张西望、伸懒腰。翻拍或点击后 5 秒内不触发。
- 打盹（`rest`）只在很长时间没人操作时才出现，默认 5 分钟，课件里可以改，设为 0 就不打盹。讲课时在一页上讲一两分钟很常见，形象不应该在讲者说话时睡着。
- 开启「减少动态」时没有空闲动作，也不打盹。

### 7.5 各风格的形象

| 风格 | 形象 |

| 水彩田园 | 朵朵：一朵圆滚滚的水彩小积云 |
| 像素游戏 | 小旗：戴毛线帽、背一面三角旗的像素小向导 |
| 科技暗黑 | 微光：悬浮的钛灰小方块机器人，一条冰蓝眼灯 |

### 7.6 用户自己的形象

自定义形象用一种「部位网格」格式：一张像素网格，每格记的是部位（头发、皮肤、眼睛、衣服等），不是颜色。四个姿势共用一个头，各有一份身体；眨眼、笑眼、闭眼用少量格子的差异来改。颜色和质感交给「皮」：每种风格提供一套皮，同一个形象换到哪种风格都像一家人，比如水彩风是铅笔线加水彩，新粗野风是粗黑描边加硬阴影，水墨风是浓墨加一点朱砂。

做出这种形象有两条路：

1. **形象工坊**：一个本地页面，选一张图片，自动裁出头部、缩到网格、减色，套上通用的身体骨架生成四个姿势；用户可以在网格上点格子改，满意后存成形象文件放进课件。这条路不需要模型会看图，任何模型都能用。
2. **能看图的模型手绘**：照着图片按部位网格格式画一个更精致的版本。

用户的照片只在本机用，不复制进 skill，也不上传到任何地方。

## 8. 屏幕适配

- 舞台按 1920×1080 设计，窗口里等比缩放（contain），背景铺满窗口，内容居中。
- 舞台外面有一层固定铺满窗口、裁掉溢出的外框，否则窄窗口会被 1920 宽的舞台撑出滚动条。
- 1440、1366、1280 这类笔记本和平板横屏按比例缩放；不是 16:9 的窗口（比如 1500×700）内容也要完整、不出滚动条。
- 平板竖屏和手机竖屏自动进入阅读模式（见 5.1 第 17 条）。
- 触屏：左右滑动翻页，点屏幕右侧前进、左侧后退。

## 9. 字体

- **霞鹜文楷**（手绘风）：带完整字库。完整字体按字符范围切成很多小块，课件用 `unicode-range` 只加载用到的字所在的块，打包时也只带这些块，所以一个字都不缺，发出去的课件依然不大。
- **缝合像素字体**（像素风，只有像素游戏用）：不切块，整份随 skill 带着，见下面单独一条。
- 霞鹜文楷的字体文件不放进仓库和 skill，skill 里只带一份切块清单（`fonts/wenkai.json`，记着每块的路径、字重、unicode-range 和校验值）。霞鹜文楷取自 npm 包 lxgw-wenkai-webfont，版本固定，常规和粗体两个字重共 194 块、约 8.8 MB。第一次需要时按清单从 npmmirror、jsDelivr、unpkg 三个镜像依次下载（npmmirror 在国内最快，排第一），逐块校验后存到本机的 `~/.li-talk-skills/fonts/`，之后一直复用；做课件时从这里复制进课件目录，浏览器只加载用到的那几块。
- 下载失败不卡流程：先用 skill 自带的常用字小字库，缺的字回退到系统楷体，下次再下载。
- **缝合像素字体随 skill 带**：用的是 Fusion Pixel Font（缝合像素字体）12px 比例宽度的简体中文版（2026.11.10），一个完整的 woff2，694,824 字节（约 679KB），和 4 份 OFL 许可证（缝合像素字体本身，以及它缝合的方舟像素、Cubic 11、Galmuri 三个上游）一起放在 `template/vendor/fonts/pixel/`。这和上面霞鹜文楷「字体文件不放进 skill」的做法不同，原因是 npm 上没有它的切块包，没法照霞鹜文楷那样按清单从镜像下载、只带用到的字块；整份不到 700KB，随 skill 带着最简单可靠。`new` 只在选了像素游戏时把这个目录复制进课件（规则是通用的：模板里有 `vendor/fonts/<风格键名>/` 的风格，选了它才带），没选的课件不带；风格 CSS 用相对路径 `../vendor/fonts/pixel/…` 引用，离线双击照样能用。搭好骨架后才换成像素游戏时，要手动把这个目录复制过去（`guide` 给的换风格步骤里写了）。
- **现代风**用系统自带的黑体、宋体字体栈，等宽字用系统的等宽字体栈，不另带字体。
- 引擎启动时先等字体：点名加载霞鹜文楷，再等 `document.fonts.ready`（风格自带的字体、页面用到的字块都算在内），最多等约 2.5 秒，然后才量主题行、署名位置和形象落脚点，免得按退回的字体量偏。
- 两种字体都是 OFL 许可，许可证随字体一起放。

## 10. 脚本命令与自检

### 10.1 命令

| 命令 | 做什么 |
|---|---|
| `tour [--skip]` | 打开新手教程课件并记下看过了；`--skip` 记下用户先不看。第一次用时 `guide` 会让 AI 先问 |
| `guide [课件目录]` | 看当前做到哪一步，告诉 AI 下一步做什么、该问用户什么（带选项）、可以这样对 AI 说；刚装好时顺带检查 Node、字体和更新 |
| `styles [--open]` | 列出所有风格：样子、适合讲什么、属于哪一类；`--open` 打开样册 |
| `materials <素材目录>` | 列素材清单：文字（字数）、图片（尺寸）、视频；生成截图说明表 |
| `new <课件目录> --title … --scenes …` | 搭骨架：复制引擎、选中的风格和形象、vendor 和字体，生成封面、目录、章节空壳和结尾 |
| `mascot` | 打开形象工坊 |
| `open <课件目录>` | 用系统浏览器打开课件 |
| `check <课件目录>` | 不开浏览器的检查 |
| `check <课件目录> --browser` | 后台浏览器自检，出文字报告；`--pages 3-5` 只查几页，`--shots` 另存截图给能看图的模型 |
| `pack <课件目录>` | 打包成一个能单独发出去的目录和压缩包，只带用到的文件和字体块 |
| `upgrade <课件目录> [--yes]` | 升级这份课件的引擎、风格和形象；不带 `--yes` 只预览 |
| `fonts` | 下载或检查本机的字体缓存 |
| `version` | 版本、安装位置、上次检查更新的结果（不联网） |
| `update` | 立即检查并更新（平时每天第一次运行命令时自动更新） |

退出码：0 没问题；1 有错误；2 环境问题，比如 Node 版本太低。

### 10.2 不开浏览器的检查

- id 重复或缺失、缺标题、缺主题行；
- 用了没引入的风格、形象或不存在的组件；跨类混用风格；
- 图片或视频文件不存在；
- 页面 CSS 没以 `[data-id]` 开头；
- 带拍的元素上写了 `transform`；
- 讲词拍数和页面对不上，每页拍数不在 2 到 4 之间；
- 讲词总字数和估算时长；
- 越过技术边界：出现 `import`、`fetch`、CDN 链接、网络字体。

检查在一个隔离的假环境里执行章节文件，只收集 `Deck.add` 的参数，不碰浏览器和网络。某一章运行出错时，明确报「这一章没查到」，不静默跳过。

### 10.3 后台浏览器自检

- **怎么跑**：先找本机的 Edge 或 Chrome（Windows 一定有 Edge），用无头模式打开课件，不弹窗口。引擎有一个自检模式：逐页逐拍直接跳到每拍的最终状态，量完把结果写进页面，脚本读出来。找不到浏览器时，起一个本机临时服务，用系统默认浏览器打开课件跑一遍，结果传回脚本。全程只用 Node 自带的模块。
- **尺寸**：1920×1080、1440×900、1280×720、1024×768，以及手机竖屏 390×844 的阅读模式。
- **量什么**：
  - 元素超出舞台；文字溢出容器；文字块互相重叠；
  - 字被形象或气泡挡住；进了风格的禁区（活页孔、粉笔槽、主题行和节拍指示所在的角）；
  - 字号小于 34px；
  - 可读性（提醒）：文字和身后底色的对比度不到 3:1（讲过变淡的也算）；竖排太长（一块超过 12 个字、一页超过 24 个字）；某一拍出现的字到最后一拍看不见了（`data-transient` 的过场字不算）；
  - 退回第 0 拍后内容没收干净；
  - 页面比窗口宽或高（出现滚动条）；
  - 控制台报错、图片或视频加载失败。

### 10.4 报告长这样

```
自检报告：12 页 38 拍 × 5 个尺寸，3 个错误、2 个提醒

错误
  第 4 页 p04「三种安装方式」第 2 拍｜1440×900
    第 3 张卡片的文字超出卡片底边 46px（卡片高 300，内容高 346）
    → 删减这张卡的文字，或去掉卡片的固定高度
提醒
  第 7 页 p07 第 1 拍｜1920×1080
    形象的气泡压住了标题右端 18px
    → 在目标元素上加 data-mascot-dx="-60"
```

### 10.5 规矩

- 错误必须清零，才能把课件给用户看。
- 提醒由 AI 逐条判断：要么改，要么说明为什么不改。

## 11. 仓库、安装与更新

### 11.1 仓库结构

```
li-talk-skills/                  仓库根（公开，MIT）
  README.md、README.en.md         图文说明：是什么、怎么装、怎么对 AI 说、风格一览
  CHANGELOG.md                    每一版的要点，自动更新时转述给用户
  LICENSE                         MIT；vendor 里各个库保留自己的许可证
  .claude-plugin/                 Claude Code 插件方式安装用
  docs/                           设计文档
  build.mjs                       发版前生成文件清单、做干净度检查
  skills/li-talk-skills/          真正装到用户机器上的部分
    SKILL.md                      给 AI 的操作手册，500 行以内
    manifest.json                 版本号和每个文件的校验值
    fonts/wenkai.json             字体切块清单；字体文件首次使用时从镜像下载
    references/                   写页面的说明、讲稿格式、风格手册、样板页、自查清单、加新风格
    template/                     课件骨架：入口、引擎、风格、形象、样板页、vendor、形象工坊
    scripts/li-talk.mjs           唯一的脚本入口（另有 lib/ 下的模块）
```

`SKILL.md` 写给之后使用它的 AI 看，讲清为什么这么做，不只是一串命令。`description` 覆盖各种问法：做分享稿、演讲稿、汇报、技术分享、培训课件、网页版幻灯片、要演讲者视图、要一拍一拍地讲；也写清不适合什么：要导出 pptx 或 pdf 的、纯文档、数据看板。

### 11.2 安装

- 命令行：`npx skills add xiaoli1999/li-talk-skills -g -a claude-code -y`。用 Codex 就把 `claude-code` 换成 `codex`，用 Cursor 换成 `cursor`。
- Claude Code 也可以用插件方式装。
- 不想敲命令的，直接对 AI 说「从 GitHub 仓库 xiaoli1999/li-talk-skills 安装到全局，装好后带我上手」。
- 只装到全局目录，不装进任何项目。

### 11.3 自动更新

- 每天第一次运行任何命令时，同时去 GitHub 和 jsDelivr 镜像读 `manifest.json`，取版本号更高的那个。
- 有新版时，只下载校验值变了的文件。全部下载完、校验通过后再一起替换，中途失败不会留下新旧混在一起的一套。新脚本替换前先过语法检查。
- 更新后输出「已自动从 x 更新到 y」和 CHANGELOG 要点，AI 转述给用户，并提醒新开对话后新的使用说明才生效。
- 网络不通或更新失败，不影响这次的命令，第二天再试。插件方式安装的，改为提示运行 `claude plugin update`。
- 只认正式版本，不提供关闭开关。
- 本机的记录都放在 `~/.li-talk-skills/` 里：更新检查记录、字体缓存。

**实现**（`scripts/lib/update.mjs`，0.1.0 已做）：

- **记录**：`~/.li-talk-skills/update.json`，字段 `day`（本地日期，今天查过就不再查）、`lastCheck`（检查时刻）、`ok`、`result`（一句话结果，`version` 和 `guide` 显示它）、`latest`（读到的最新版本号）、`source`（从哪个来源读到的）。开始检查前先记下今天查过：同时运行的别的命令不再查，这次中途被关掉也等明天再试。
- **超时**：自动更新时读清单总共 6 秒，一个来源先回来后再等另一个 1.5 秒；下载阶段总共 30 秒（单个文件 15 秒）；读 CHANGELOG 3 秒。`update` 命令放宽：读清单 15 秒、宽限 3 秒、下载最多 10 分钟。
- **整包替换四步**：
  1. 按新清单比对本地文件的**实际**校验值，只下载对不上的（变了的、新增的、本地被改坏的），逐个校验 sha256；先从给出清单的来源下，不行再换另一个来源。
  2. 在临时目录拼出完整的新版（没变的从旧目录复制过去），整体核对：文件一个不多一个不少、校验值全对、`version.txt` 和清单的版本号一致、新下载的 `.mjs` 过 `node --check`。临时目录和安装目录放在同一块磁盘上，改名才是瞬间完成的。
  3. 旧目录整体改名成备份 → 新目录改名到原位置 → 删备份。
  4. 任何一步失败，旧目录不动；新目录就位失败就把备份改回原名。改不回时报出备份所在的位置，请用户手动改名。
- **更新后重跑**：这个进程里已经加载的是旧模块，所以入口用新代码在子进程里把这条命令重新跑一遍（今天已经记过，不会再查一次）。`version`、`update` 两个命令自己处理更新，不在命令开始前自动检查。
- **不自己替换的情况**：在仓库里直接运行（skill 目录上两级有 `.git`）时跳过；插件方式安装的只提示运行 `claude plugin update li-talk-skills@li-talk-skills`。
- **换来源**：环境变量 `LI_TALK_UPDATE_BASE` 指向仓库根目录（本地路径或 http 地址，多个用英文逗号分开），替换默认的 GitHub 和 jsDelivr，测试和自建镜像用。
- **更新锁**：`~/.li-talk-skills/update.lock`，同一时间只有一个进程在替换文件；锁超过 10 分钟还在，当作上次中途退出留下的。
- **更新说明**：从 CHANGELOG 里取「当前版本之后、新版本为止」各版的要点，只取 `## x.y.z` 下面顶格的 `- ` 条目，每条只留第一句，最多列 12 条。

### 11.4 已经做好的课件

- skill 更新时不碰已经做好的课件，讲者可能正要上台。
- 想升级时运行 `upgrade <课件目录>`：先列出会替换哪些文件（引擎、风格、形象、vendor）、版本从几升到几；用户确认后才替换，原文件备份一份；用户写的页面（`slides/`）和讲稿永远不动。

### 11.5 发版

合进主分支（`master`）由作者操作，合进去就是发版；自动更新只读 `master`，所以 `dev` 上的半成品不会影响任何用户。步骤：

1. 改 `skills/li-talk-skills/version.txt`（正式版本号 x.y.z）。
2. 写 CHANGELOG：最上面一版的标题是 `## x.y.z`，和 `version.txt` 一致；要点用顶格的 `- ` 写，自动更新时每条只取第一句转述给用户，所以第一句就要把事说清，细节放后面或放缩进的子条目里。
3. 运行 `node build.mjs --release`：干净度检查（本机绝对路径、内部词、版本号和 CHANGELOG、换行、文件是否都进了 git）→ 生成 `manifest.json` → 核对清单和文件 → 全量测试。哪一步没过就停下。
4. 把改动连同 `skills/li-talk-skills/manifest.json` 一起提交。
5. 推开发分支：`git push origin dev:dev`。
6. 作者在 GitHub 上把 `dev` 合进 `master`。
7. 合并几分钟后，在临时目录装一份旧版，运行任意命令，确认能自动更新到新版。

平时开发中改了 skill 目录里的文件，也要重新运行 `node build.mjs --manifest` 生成清单，`node build.mjs --check` 才会通过。

## 12. 实施顺序与分工

**分工**：主会话把控全局，负责设计、接口、联调、汇总。写代码交给子代理，每个子代理只改分给它的文件，一次做完。

**顺序**（前一批没过，后一批不开始）：

| 批 | 做什么 | 怎样算过 |
|---|---|---|
| 0 | 挑风格（已完成：两轮样页，15 种全部定稿） | 作者明确选定 |
| 1 | 搭仓库骨架；拿一份已有的成熟引擎做起点，拆成多个文件，改成风格可插拔，抽出方格纸、黑板、像素手账、工位桌面 4 种风格 | 作者本机的一份 41 页旧课件在新引擎下能从头翻到尾再退回来，除形象外观感和原来一致（旧课件不进仓库） |
| 2 | **并行**：引擎新能力分成几块；形象接口和形象工坊；其余 11 种风格每种一个子代理（9 种新风格从定稿样页转成风格文件，蓝图、漫画从旧样页移植）；原有 6 种风格的形象（先出样子给作者定稿）；脚本分成几块；字体切块 | 各块自测通过 |
| 3 | 样板页和样册；`SKILL.md`、`references/`、README | 所有样板页 × 所有风格 × 5 个尺寸，自检报告清零 |
| 4 | 整体验证（见第 13 节）→ 修订 | 见第 13 节 |
| 5 | 发版：干净度检查，生成文件清单，推 `dev`，作者合进 `master`；再用临时目录真装一遍，测安装和自动更新 | 装上就能用，更新能拉到新版 |

每做完一块就提交并推 `dev`。样册出来时请作者过一遍，发版前再过一遍。

## 14. 风险与已知限制

- 用 `file://` 打开时，主窗口一刷新，演讲者窗口就连不上，窗口底部变红提示，回主窗口再按一次 S 即可。
- 液态玻璃的折射只有 Chrome、Edge 支持，其他浏览器退成轻模糊。
- 毛玻璃、液态玻璃在配置差的投影电脑上可能吃力，靠帧率保护自动关掉贵的效果。
- 深色风格（黑板、蓝图、科技暗黑、像素游戏）投到幕布上容易发灰，文字已经提亮，仍建议在现场设备上试一次。
- 像素游戏在缩放比例不是整数的窗口里，像素会被重新采样，不再绝对锐利。
- 总览的缩略图是页面 DOM 的克隆、摆到最后一拍：页面自己写的 `onBeat` 动画改出来的样子缩略图里没有；黑板粉笔质感这类只在当前页套的滤镜，缩略图里不套。
- 形象工坊自动像素化只能做到「认得出」，想要更像，需要在网格上手动改，或者让能看图的模型手绘。
